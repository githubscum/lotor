Start here.

Lotor is a witness layer for AI agent sessions: every tool call your agent makes is recorded into a hash-linked, append-only chain of receipts, signed at the time of the act, held by you and not by a vendor. This page is the walkthrough. It is also the beginning of the FAQ, and it grows the way the rest of this project does: by questions that actually got asked.

1What am I looking at?

Three pages, one record. /lotor is the product view: your days as blocks, each session showing where its work landed. /events is every receipt on the chain, filterable. /control is the mode panel and the witness board. Everything on all three pages is derived from one file: the receipt chain. Nothing here is inferred, and nothing here can be edited from a browser, because the chain is append-only and this server is a reader.

2Why is there data here already?

Because a blank page teaches nothing. Until your own chain writes its first receipt, the UI serves a synthetic sample shaped after the double-blind experiment behind "The Bones Do Remember": three sessions across three days, a gate that denies and then approves under a signature, a warn-mode day, a loose day, and one session that opened and never closed, because the crash you cannot see is the one worth recording. Every page shows a DEMO banner while this data is up. Every path in it is under C:\demo\. The moment your real chain has one receipt, the sample disappears and never comes back.

3Your first real receipt

From the repo root:

npm install
npm run setup      # sets your signing passphrase; the private key is never on disk
# then register the four hooks in your Claude Code settings (README, "Install")

Open any Claude Code session and close it. That is the whole hydration: the SessionStart hook writes a session-open receipt, the SessionEnd hook parses the transcript into a session receipt with a transcriptHash binding it to the exact bytes it summarizes. Refresh /lotor and the demo banner is gone. Your record has begun.

4The gate, and the three modes

Recording is half the product. The other half is the gate: actions matching your policy rules stop and stage a request, and nothing proceeds without a signature only the operator can produce. The passphrase-derived key never sits on disk, so the agent being gated cannot sign its own way through. Modes set the temperature: herded gates, grazing warns, loose only records. Editing the gate's own source gates in every mode, including loose, because the one thing an agent must never quietly change is the thing that stops it. See /control for what is currently gating, warning, and off.

5Reading a receipt

On /events, click any gate event. It expands into its decision path: tool call, rule matched, canonical params digest, how long the request waited for a signature, the single-use nonce, the verdict. A gate verdict is deterministic: the same recorded facts always produce the same outcome, so the path IS the explanation. Receipts written before a given instrumentation upgrade render their missing fields dimmed as "unrecorded" rather than guessed at, and each verdict carries the hash of the matcher build that produced it, so "the rules changed since then" is a readable fact instead of a suspicion.

6The QR export

The export → QR button on /lotor turns a spine (a short self-description you write) into a signed, scannable bundle bound to your chain head. Another LLM can boot from it. Two guardrails: the server rejects spines carrying key material or secret-shaped strings and tells you what it matched, and the publish button says what it means: a QR is a broadcast, and anyone who scans it reads the spine. The chain key signs server-side and never reaches the browser.

7What none of this proves

Capture is self-attested. The chain proves tamper-evidence, not completeness: what was never recorded is not proven absent. Silence is not safety.

Receipts carry behavior, never intent. Which tools ran, with what parameter digests. Not why. Captured thinking digests are self-report: the stated reasoning is on the record, which is never the same claim as "we can tell what it was thinking."

A record you hold alone is an alarm, not a proof. Convincing a second party requires a second party: a head hash written down off this machine. The witness board on /control shows UNWITNESSED until one exists, on purpose.

The full inventory lives in KNOWN-LIMITS.md, which is the most load-bearing file in the repo: defects disclosed by the party the disclosure costs.
