## Why

The self-mod gate reads protected paths from the command string. `git apply x.patch`,
`git am x.mbox` and `patch -p1 < x.diff` take their write targets from INSIDE the patch file,
so a core edit passes with no gate stop. The fix: when a command applies a patch, read the
patch file(s) and return the target paths so the gate can classify them; fail closed when the
patch source cannot be read.

## File 1: proposals/l82-patch-targets/patch-apply.js

ES module (the repo is "type": "module"), Node built-ins only. Export exactly one function:

```
export function patchApplyTargets(cmd, cwd, readFile)
```

- `cmd`: the raw command string. `cwd`: directory to resolve relative patch paths against.
  `readFile(absPath)`: returns the file text or throws (tests inject a fake; default it to
  `(p) => fs.readFileSync(p, 'utf8')` when not given).
- Returns `null` when the command applies no patch. Otherwise returns
  `{ targets: string[], failClosed: boolean, inline: boolean }`.

Detection. Split `cmd` into segments on `;`, `&&`, `||`, `|`, newline. A segment applies a
patch when, after optional leading whitespace and `(`:
1. it is `git` (optionally path-prefixed, e.g. `/usr/bin/git`, `git.exe`), followed by zero or
   more git global options (`-C <dir>`, `-c <k=v>`, `--git-dir=...`, `--work-tree=...`,
   `--no-pager`), then the subcommand `apply` or `am`; or
2. its first word is `patch` (optionally path-prefixed, `patch.exe` too).
`npm version patch`, `kubectl patch`, `git add --patch`, `git log -p` and `echo patch` are NOT
patch applications. A segment whose previous separator was `|` is still checked (the patch
verb reading a pipe is the failClosed case below).

Non-writing forms return null for that segment: `git apply` with any of `--check`, `--stat`,
`--numstat`, `--summary` and without `--apply`; `git am` with `--abort`, `--quit`,
`--show-current-patch`.

Patch sources for a matching segment:
- `git apply` / `git am`: every non-flag token after the subcommand (strip surrounding single
  or double quotes). Flags start with `-`. Treat `--directory=`, `--include=`, `--exclude=`,
  `-p<n>`, `-C<n>` as flags with attached values.
- `patch`: the value of `-i <f>`, `-i<f>`, `--input=<f>`; plus every positional token (the
  first positional is the file to patch, the second the patch file: put BOTH in sources AND
  put every positional token in `targets` directly). Options that take a separate value and
  whose value is NOT a source: `-p`, `-d`, `-o`, `-r`, `-D`, `-F`, `-B`, `-z`, `-V`, `-Y`, `-g`.
- either verb: the token after a `<` redirect in the segment (`< x.diff` and `<x.diff`).
- If the segment contains `<<` (a heredoc), set `inline: true` and do not require a source.

Reading: resolve each source against `cwd` (absolute stays absolute; fold `\` to `/` before
deciding absolute vs relative; a Windows drive path like `C:/x` is absolute). A token starting
with `<(` or containing `$(` or a backtick is unreadable. If any source cannot be read,
`failClosed = true`. If the segment has no source, is not inline, and is not fed by a pipe,
`git am` / `git apply` / `patch` read stdin: `failClosed = true`. Piped input: `failClosed = true`.

Targets from patch text, line by line (accept CRLF): `--- <p>` and `+++ <p>` (drop a trailing
tab and anything after it, skip `/dev/null`), `diff --git a/<x> b/<y>` (both), `rename from`,
`rename to`, `copy from`, `copy to`. Strip a leading `a/` or `b/` from each, and ALSO keep the
unstripped form (the gate matches substrings, more strings is safer). Deduplicate. An mbox for
`git am` uses the same lines.

No regex literal may contain a protected path. Keep the file under 200 lines with short
comments in the repo's style (why, not what).
