# WO-L82-03: close the fail-open cases in the patch-target classifier

Found 2026-11-14 in the review of PR #92 (brain daily note, LIMIT line). The
classifier in `proposals/l82-patch-targets/patch-apply.js` returns `null`
(meaning "not a patch-apply command, nothing to gate") for commands that DO
apply a patch. `null` is fail-open. Fix every case below so it is either
matched with its targets or matched with `failClosed: true`.

## Scope gate (hard)

- Edit ONLY `proposals/l82-patch-targets/patch-apply.js` and
  `test/l82-patch-targets.test.js`. Touch nothing else. Do not commit.
- Keep every existing test passing. Do not change existing assertions.
- No new dependencies. Plain ESM, same style as the file.

## Cases that must stop returning null (each gets a test)

Use `/repo/x.patch` from the test's FILES map as `x` (cwd `/repo`), so the
expected targets include `src/chain/index.js`.

1. `if true; then git apply x.patch; fi` - shell keywords. In `skipHidden`,
   skip leading reserved words `if then else elif do while until ! { time`
   (and a lone `(`) the same way wrappers are skipped.
2. `true & git apply x.patch` - a single `&` is a command separator. Split on
   it in `scanCommand`, but NOT on `&&` (already handled), `>&`, `<&`, `&>`,
   or `2>&1`. Suggested split regex:
   `/(&&|\|\||(?<![<>&|])&(?![>&])|[;|\n\r])/` - verify the `2>&1` and `&>`
   forms still parse as one segment.
3. `{ git apply x.patch; }` - `{` handled by case 1; a trailing `}` token in
   a later segment must not break anything.
4. `! git apply x.patch` - handled by case 1.
5. `env -u FOO git apply x.patch` - give `env` the value flags `-u`, `-C`,
   `--unset`, `--chdir`. Also `env -S "git apply x.patch"` (split-string):
   when env carries `-S`/`--split-string`, scan the rest of the segment as an
   inner command like `shell -c` does, or set failClosed; either is fine,
   say which in a comment.
6. `git --git-dir x apply x.patch` and `git --work-tree w apply x.patch` -
   in the git global-option loop, `--git-dir`, `--work-tree`, `--namespace`,
   `--super-prefix`, `--config-env`, `--exec-path` WITHOUT `=` take the next
   token; WITH `=` they are one token.
7. `git -P apply x.patch`, `git --paginate apply x.patch`,
   `git --bare apply x.patch`, `git --no-optional-locks apply x.patch` -
   any other token starting with `-` before the subcommand is a
   self-contained global flag: advance one and keep looking.
8. `git apply /dev/stdin` and `git apply -` and `patch -i /dev/stdin` and
   `git apply /dev/fd/0` and `git apply /proc/self/fd/0` - these are stdin.
   Do NOT call the reader on them (readFileSync on /dev/stdin can hang). Set
   failClosed and skip the read. Test it with a reader that THROWS a
   distinctive error if called with any of those paths, and assert
   failClosed is true and the reader was not called.
